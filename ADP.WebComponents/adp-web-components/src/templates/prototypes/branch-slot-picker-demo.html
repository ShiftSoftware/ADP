Branch-aware slot picker

The dealer decides what's bookable. Pick a branch and the field asks /public/calendar what that branch is actually open for — then shows only real days and real times. Closed days never render, so there is nothing for a customer to choose and have rejected later.

What each region is

Two visible rows, one network call. Changing the day is a local re-render; only changing the dealer refetches.

dealer select

Existing companyBranchId field. Its meta already carries company, department and brand — every parameter the calendar call needs.

day strip

One chip per day the API returned, horizontally scrollable with snap points. Closed days are absent rather than disabled — no dead targets.

time pills

The selected day's Times[], wrapped in a grid. Re-rendered from cache when the day changes, so there is no second request.

states

Idle before a dealer is chosen, skeletons while loading, and real copy for empty and error — the error path still lets the form submit.

Where each part gets its data

The three quirks at the bottom belong to the endpoint, not the design — they will show through whatever UI sits on top.

Region Source Notes
Dealer select /public/company-branch Already wired. Keeps the full branch object in meta.
Day strip /public/calendar → one chip per Date Never more than 15 chips — the endpoint applies .Take(15).
Time pills The selected day's Times[] Arrive as yyyy-MM-dd hh:mm tt in invariant culture, so AM/PM is literal English and must be re-formatted per locale.
Empty state A response with no entries Real case: a holiday covering the whole 15-day window.
Gap before the first chip Endpoint filter Nothing sooner than 48 hours is ever returned.
A week-long gap, two branches only Endpoint filter Company 1 / branches 45 and 50 have slots shifted a week forward. Expected, not a rendering fault.
